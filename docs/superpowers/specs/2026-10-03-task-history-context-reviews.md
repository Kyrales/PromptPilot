# Ревью контекста задач

## Раунд 1 — gpt-6.1-sol, high

Проверена спецификация и реальные пути запуска. Приняты и внесены пять замечаний:

1. Старые `tasks.result` не являются надёжным источником роли assistant: herdr
   хранит терминальный текст, headless-итог может включать диагностику. Такой итог
   остаётся в карточке задачи; в историю включаются только достоверные сообщения.
2. Ручные сообщения в произвольную панель нельзя приписывать последней задаче.
   Для сбора определены границы конкретной попытки; продолжения не включаются.
3. Добавлено отдельное удостоверение для GET-маршрутов контекста вместо передачи
   агенту общего API-токена с правами управления очередью.
4. Проект идентифицируется по Git common directory и машине, включая уже
   существующие worktree. Для не-Git каталогов используется абсолютный путь.
5. Попытка запуска получает отдельный ID. Повторное исполнение не определяется
   по счётчику retry; доставка дополнений учитывается отдельно.

Уточнены срок жизни снимков (1 час) и неполная история detached-запусков.

## Раунд 2 — gpt-6.1-sol, high

Повторно проверены исправленная спецификация и код. Первый раунд признан исправленным.
Приняты два дополнительных уточнения:

1. Удаление задачи удаляет снимки и инвалидирует курсоры между порциями.
2. Существующая herdr-панель получает новый явный контекст каждой задачи:
   нельзя полагаться на её старое окружение, а проект определяется по фактическому cwd.

Оба условия добавлены в спецификацию и проверки плана. Других блокирующих
противоречий ревьюер не обнаружил.
