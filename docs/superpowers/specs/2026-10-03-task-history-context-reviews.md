# Ревью контекста задач

## Раунд 1 — gpt-6.1-sol, high

Проверена спецификация и реальные пути запуска. Приняты и внесены пять замечаний:

1. Старые `tasks.result` не являются надёжным источником роли assistant: herdr
   хранит терминальный текст, headless-итог может включать диагностику. Такой итог
   остаётся в карточке задачи; в историю включаются только достоверные сообщения.
2. Ручные сообщения в произвольную панель нельзя приписывать последней задаче.
   Для сбора определены границы конкретной попытки; продолжения не включаются.
3. Добавлено отдельное удостоверение для GET-маршрутов контекста вместо передачи
   агенту общего API-токена с правами управления очередью.
4. Проект идентифицируется по Git common directory и машине, включая уже
   существующие worktree. Для не-Git каталогов используется абсолютный путь.
5. Попытка запуска получает отдельный ID. Повторное исполнение не определяется
   по счётчику retry; доставка дополнений учитывается отдельно.

Уточнены срок жизни снимков (1 час) и неполная история detached-запусков.

## Раунд 2 — gpt-6.1-sol, high

Повторно проверены исправленная спецификация и код. Первый раунд признан исправленным.
Приняты два дополнительных уточнения:

1. Удаление задачи удаляет снимки и инвалидирует курсоры между порциями.
2. Существующая herdr-панель получает новый явный контекст каждой задачи:
   нельзя полагаться на её старое окружение, а проект определяется по фактическому cwd.

Оба условия добавлены в спецификацию и проверки плана. Других блокирующих
противоречий ревьюер не обнаружил.

## Финальное ревью реализации — gpt-6.1-sol, high

Независимый ревьюер проверил изменения от `62ab91c` до `4353aa1` и запустил
целевые тесты. Приняты и исправлены три воспроизводимые ошибки:

1. Сохранение снимка после чтения в той же отложенной SQLite-транзакции могло
   завершаться `SQLITE_BUSY_SNAPSHOT`, если работающая задача успевала записать
   данные. Чтение теперь завершается отдельно; готовый снимок сохраняется в новой
   транзакции с повторной проверкой существования обеих задач.
2. Сообщения сессии без ID получали номер строки внутри скользящего хвоста файла.
   При росте файла номер менялся, вызывая дубли. Теперь используется абсолютное
   смещение записи в байтах.
3. Новое уточнение к старой задаче скрывало исходное задание. Восстановление
   исходного prompt теперь зависит от наличия именно записи prompt, а не любых
   сообщений; неполнота старой истории остаётся явно обозначенной.

Четыре регрессионных теста сначала воспроизвели ошибки, затем прошли после
исправлений. Дополнительно проверено чтение работающего процесса, сохранение
сообщений после отмены и доступность истории после удаления исходного JSONL.
Ревьюер повторно проверил исправления: все три замечания закрыты, 18 затронутых
тестов прошли с `-W error`. Итоговый полный набор: **1008 passed** с `-W error`;
ruff и `git diff --check` без ошибок. Wheel собран и содержит актуальные модули.

Живые SSH/herdr-сервисы и собранный Windows exe не проверялись: транспорт
проверен через подмену SSH и настоящий отдельный Python-процесс, herdr — через
подмену сервиса с реальными файлами сессий. Неподдерживаемые источники и старая
история возвращают явные признаки неполноты; удалённый доступ требует настройки
`PP_CONTEXT_URL` и установленного `pp` на машине агента.
