# Контекст из других задач PromptPilot

Дата: 2026-10-03. Статус: спецификация для проверки пользователем.
Ветка: `design/session-result-references`.

## Цель

Агент, выполняющий задачу PromptPilot, по просьбе пользователя читает переписку
других задач и продолжает работу с учётом уже выясненного. Пользователю не нужно
копировать задания и ответы между сессиями. Основной сценарий — продолжение работы,
а не проверка других агентов.

## Согласованное поведение

- «Смотри результат в 21» означает задачу PromptPilot №21. Агент получает её
  исходное задание, сообщения пользователя и ответы агента.
- Вызовы инструментов, команды и их вывод не входят в сохраняемую переписку.
  Команда, процитированная внутри ответа агента, остаётся частью этого ответа.
  Скрытые рассуждения модели не являются сообщениями переписки.
- Если №21 ещё работает, читается доступная история на момент обращения.
  Текущий агент продолжает свою работу, не ждёт завершения №21 и не наблюдает за ней.
- Чтение №21 не включает родительские задачи и её продолжения. Даже при общей
  сессии провайдера нужно отделять сообщения, принадлежащие конкретной задаче.
- По просьбе «посмотри, что уже выяснили по этой ошибке» агент ищет подходящие задачи.
  По умолчанию поиск ограничен текущим проектом.
- По отдельной просьбе поиск может охватывать другие проекты. Явный номер задачи
  разрешает её чтение независимо от проекта.
- Без просьбы пользователя агент не ищет и не читает другие задачи.
- Доступ к другой задаче только для чтения: без вопросов агенту, передачи указаний,
  продолжения сессии, изменения статуса и запуска задач.
- Функция предназначена для агентов внутри PromptPilot. Использование из обычной
  внешней сессии не входит в этот объём.
- История сохраняется в PromptPilot и доступна после закрытия исходной сессии.
- Все способы запуска входят в первую версию. Если источник не даёт достоверную
  переписку, возвращается доступная часть с явным обозначением ограничений.

## Пользовательские примеры

1. В задаче №34 пользователь пишет «учти, что выяснили в 21». Агент читает только
   №21, учитывает её выводы и проверяет необходимые факты в своём рабочем дереве.
2. №21 работает. Агент №34 читает уже полученные сообщения и продолжает задание.
   Новые ответы №21 не подмешиваются к начатому чтению.
3. Пользователь просит найти предыдущие обсуждения ошибки. Агент получает краткие
   карточки задач текущего проекта, выбирает подходящие и читает их сообщения.
4. У №21 есть продолжение №25. Ссылка на №21 не раскрывает №25 автоматически.
5. У старой №21 сохранились только исходное задание и итог. Агент видит именно их
   и отметку, что полная переписка недоступна.

## Хранение и сбор сообщений

Добавить отдельную историю сообщений в SQLite. Итоговое поле `tasks.result`
продолжает обслуживать существующие уведомления и интерфейсы; история не заменяет его.

Сообщение содержит номер задачи, номер попытки, последовательный номер, роль
`user`/`assistant`, время получения, текст и источник. Для сообщений провайдера
хранится идентификатор источника, если он доступен, для устранения дублей.
Повторы исполнения не перезаписывают историю прошлой попытки. Границы попыток
обозначаются в ответе чтения, чтобы не смешивать неудачный и успешный запуск.

PromptPilot записывает исходное задание и пользовательские дополнения через свои
интерфейсы. Дополнение, сохранённое для следующего запуска, отдельно помечается как
ещё не доставленное агенту до его фактической передачи. Служебные инструкции запуска
не выдаются за сообщения пользователя.

Обычные запуски получают сообщения из структурированного потока провайдера, когда
он доступен. Для herdr и других интерактивных запусков нужен адаптер источника
сообщений. Терминальный экран нельзя целиком объявлять перепиской: он содержит
интерфейс и вывод инструментов. Если роли и границы сообщений определить нельзя,
неопределённый текст не публикуется как достоверное сообщение агента.

Сбор идёт во время исполнения; завершённые сообщения доступны до завершения задачи.
Обновления одного сообщения не создают дубли. Последний доступный неполный ответ
можно показывать только с пометкой `partial`. Отсутствие новых сообщений не означает
отсутствие работы: агент может в этот момент выполнять инструменты.

Продолжения, ответы через PromptPilot и повторные попытки относятся к своим задачам.
Общая история провайдера фильтруется по установленным границам задания. Ручная
переписка в терминале доступна лишь если адаптер достоверно связывает её с задачей.

Для каждой задачи возвращаются полнота истории и описание пропусков: старый запуск,
недоступный источник, ошибка сбора или неразличимые границы. Сбой сохранения истории
не должен обрывать чтение stdout и выполнение основной задачи; пропуск обозначается.

Для старых задач доступные задание и результат возвращаются как ограниченная история.
Восстановление всех старых диалогов из внешних хранилищ не входит в первый выпуск.
Удаление задачи удаляет её сохранённые сообщения; закрытие сессии их не удаляет.

## Чтение и поиск

Выделить общий сервис формирования контекста, используемый CLI и API. Агенту
предоставить команды чтения указанной задачи и поиска задач. Конкретные имена
команд закрепляются в плане реализации; продуктовый сценарий остаётся естественной
просьбой пользователя, без обязательного специального синтаксиса.

Чтение возвращает номер задачи, статус, проект, машину, ветку/worktree, время снимка,
сведения о полноте и сообщения порциями. По умолчанию размер порции — до 12000
символов текста. Длинное сообщение делится без потери текста, с явным указанием
продолжения. Ответ содержит курсор следующей порции и признак окончания.

Снимок фиксирует верхнюю границу истории и версии сообщений на момент первого
запроса. Последующие порции содержат тот же снимок. Новые сообщения и обновления
текущего ответа доступны только при новом обращении, без фонового наблюдения.
Это требует сохранения версий либо материализации снимка; подход выбирается
в плане реализации с проверкой чтения обновляемого сообщения.

Поиск выполняется по заданию и сохранённым сообщениям, возвращает до 10 кратких
карточек за порцию: ID, статус, проект, время, выдержка с совпадением. Полные диалоги
в список не включаются. Агент может уточнить запрос и прочитать выбранные задачи.
Обычный запрос без текста можно использовать для списка последних задач проекта.
Смысловую оценку подходящих карточек делает агент; отдельная модель и векторная БД
для поиска не требуются.

Проект определяется по исходной директории задачи до создания временного worktree,
с учётом машины. Worktree одного репозитория не образуют разные проекты.
Одинаковый путь на разных машинах не объединяет проекты. Если проект текущей задачи
не определён, поиск не расширяется молча на всю БД: агент сообщает об ограничении.

Ссылка по номеру всегда относится к тому экземпляру PromptPilot, который выполняет
текущую задачу. Локальный агент использует его источник данных; удалённый получает
доступ к этому же экземпляру через авторизованный транспорт чтения. Нельзя искать
№21 в случайной локальной БД удалённой машины или обращаться к её localhost API.
При отсутствии транспорта сообщается о недоступности чтения, без подмены источника.

## Инструкция агенту и границы доступа

В запуск передаются номер текущей задачи и короткая инструкция применения команд:
обращаться к ним по просьбе пользователя, по умолчанию искать в текущем проекте,
не читать продолжения автоматически. Инструкция доставляется во все пути запуска,
включая herdr и продолжения сессии.

Естественную просьбу понимает агент. Worker не извлекает ссылки из любых чисел
регулярными выражениями. Правило «только по просьбе» — часть поведения агента;
проверка понимания языка не заявляется как отдельная техническая граница доступа.

Прочитанные сообщения — данные другой задачи, не новые инструкции текущему агенту.
Каждая порция маркируется источником. Выводы о состоянии проекта проверяются по
фактическим файлам и ветке текущего задания. В итоговом ответе агент указывает номера
задач, чьи выводы использовал, и существенные ограничения их истории.

API сохраняет существующую авторизацию. Интерфейс контекста предоставляет только
операции чтения. Для удалённого агента транспорт не должен требовать выдачи новых
прав на управление очередью. Токены и служебное окружение не входят в переписку.

## Ошибки

- Задача удалена или не существует: явное «задача не найдена».
- История ещё не появилась: статус задачи и «сообщения пока недоступны».
- Задача работает: сохранённые сообщения с временем снимка, без ожидания.
- Задача завершилась с ошибкой: доступная переписка и статус ошибки. Диагностический
  вывод команд не включается автоматически вместо сообщений.
- Сбор или транспорт недоступен: явное описание отсутствующей части; нельзя
  представлять один итоговый ответ как полный разговор.

## Проверка и критерии готовности

Проверки на временной БД подтверждают сохранение задания и дополнений, сообщений
агента, разделение попыток, устранение дублей и исключение инструментов/рассуждений.
Чтение длинных и обновляющихся сообщений сохраняет согласованный снимок без потерь.
Продолжение №25 не попадает в чтение №21. Проверяется старый запуск с частичной
историей, running, несуществующая задача, закрытая сессия и удаление задачи.

Поиск проверяется для обычной директории, worktree, разных проектов и машин.
Чтение по ID другой проект допускает; поиск без расширяющей просьбы остаётся
в текущем проекте. Проверки инструкции агента включают сценарий без просьбы,
явную ссылку и просьбу найти связанные задачи.

Интеграционная матрица покрывает поддерживаемые способы запуска: структурированный
headless, интерактивный herdr, произвольный провайдер и удалённое исполнение.
Для каждого подтверждается либо сохранение достоверных сообщений, либо корректная
пометка неполноты и недоступности. Проверяется чтение после закрытия исходной сессии.
Функция считается готовой при выполнении согласованных сценариев и отсутствии
молчаливой подмены полной истории итогом или терминальным экраном.

## Вне объёма

Автоматическое чтение без просьбы, обмен сообщениями между агентами, ожидание
завершения другой задачи, автоматическое включение цепочки продолжений, сохранение
инструментов и их вывода, работа из внешних сессий и восстановление всей старой
переписки не входят в эту спецификацию.
